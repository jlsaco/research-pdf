# Slide 12 — Exercise 4.B: Build Your Automation

## What this slide says
This slide (40 minutes, using Zapier or Make) has each learner build their own automation following the Trigger → AI → Delivery anatomy. It offers a menu of five options: (1) Email Analyser — Trigger: Email, AI Step: summarise, Delivery: Slack message; (2) Meeting Summariser — Trigger: new file in Drive, AI Step: summarise notes, Delivery: send to Slack; (3) Application Screener — Trigger: email with "Application," AI Step: extract + rate fit, Delivery: add to Sheet; (4) Planner — Trigger: new PRD, AI Step: generate atomic user stories, Delivery: an Epic in Jira; (5) Ticket Router — Trigger: form / email, AI Step: categorise + urgency, Delivery: create task + priority. A red warning footer advises: start simple — one trigger, one AI step, one delivery, because "a working simple automation beats an incomplete complex one."

## Key concepts
- Hands-on application of the universal Trigger → AI → Delivery structure to a real, chosen use case.
- Five concrete options, each decomposed into its three stages so the pattern is reinforced by repetition.
- Strong guidance to keep the first build minimal: one trigger, one AI step, one delivery.
- The "working simple beats incomplete complex" principle — bias toward shipping something that runs end to end.

## Notes for a Project Manager
The five options map cleanly onto common PM-adjacent pain points — screening applications, routing tickets, turning a PRD into Jira epics, summarising meetings. The Planner option in particular (PRD → user stories → Jira Epic) is a direct illustration of automating part of the backlog-grooming workflow you likely own. The headline lesson for a PM is the scoping discipline in the footer: define an MVP that runs end to end before adding branches and edge cases. This is the same "ship a thin slice first" principle that keeps projects from stalling, applied to automation.
